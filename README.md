# BiasLens

Public product name: **BiasLens**. Canonical product repository: `bitbaum/biaslens`.

Open-source investigation of questions, evidence, media, historical narratives and public arguments.
See the [consolidation ledger](docs/consolidation.md) for donor history,
source inventory and coordinated runtime identity application.
Article reports require the insight and passage-grounding fields; a malformed model response gets one bounded schema repair instead of silently falling back to an older report. Citation links in fetched pages remain article-supplied references, not independently authenticated evidence.

The first working slice takes **an article URL or pasted text** and produces a
provisional, first-principles analysis. It separates an article's factual,
normative and causal claims, notes apparent support *inside* the text, surfaces
possible framing and explains what new evidence could change the assessment.

**Bias is not the same as factual inaccuracy. A model's summary is not a
verified fact.** The article analysis is generated by an AI provider and is
not currently an independent fact-check.

## What exists

| Surface | Status |
| --- | --- |
| `/explore` | Browser-local question notebook with exact source locators, unverified annotations, notes, challenges and JSON export; no source retrieval or authentication |
| `/whitepaper` | Versioned technical working paper rendered with existing bip-kit |
| `/development` | Links canonical project context, roadmap/changelog, reviewed changes, journal and challenges |
| `/analyze` | Browser workspace for fetching an article or pasting text; provisional report, source attribution, truncation notices and downloadable versioned JSON report with a SHA-256 digest of the text actually examined |
| `POST /api/analyze` | Validated, bounded request, shared URL reader, LLM fallback and rate limiting; structured JSON responses |
| `/methodology` | Public Open Epistemic Method with a worked causal-hypothesis example and a GitHub challenge path |
| `src/lib/domain/epistemic-graph.ts` | Pure claim/evidence/relation/challenge protocol; detects gaps rather than inventing truth probabilities |
| `/api/claims/verify` | Legacy evidence **counting demonstration**, not calibrated verification |
| PostgreSQL / Drizzle | Baseline schema for outlets, articles, claims, evidence and narratives; **analysis results are not persisted yet** |

The downloadable report contains analysis, model and method versions, timestamp, and a digest of the analysed text. It is not stored server-side; a digest does **not** authenticate the original source or reproduce an unavailable model. The exact examined source text is included in the export; invented model quotations are suppressed before rendering.

### Timed-transcript Debate Arena

`/debates` now accepts a **user-supplied timestamped transcript** and computes
speaker airtime, relative speaker-seconds, intervals of cross-speaker overlap,
and time without an assigned speaker. The calculation is pure, tested and
performed entirely in the browser; no uploaded transcript is transmitted or
persisted. The demo example uses fictional speakers.

This is **not** automatic diarisation or proof of a political interruption,
bias, equal moderation, or historical accuracy. The recording, speaker labels
and transcript timestamps must be externally verified before publishing
comparative findings. Future audiovisual analysis should preserve source
timestamps and a public correction trail.

**Not yet delivered:** independent multi-source verification, calibrated
confidence, persistent public reports and moderated discussion,
audio/video debates, historical record provenance, cross-outlet comparisons,
and independent production model-provider verification. Provider availability is reported by `/api/health`; a configured credential is not proof of a successful analysis.

### Accounts and runtime setup

`/sign-in`, `/sign-up` and `/account` use **@bitbaum/accountkit** for the complete account flow: password accounts, sessions, passkeys, TOTP, profile editing, linking configured OIDC methods and deletion. Mail uses **@bitbaum/mail-kit**; mail-dependent methods are shown only when configured. Account security logic and table definitions stay in the shared package. The package is pinned to its reviewed GitHub commit because its current auth release is not published on npm.

Deploy preparation reuses Loki's database provisioner, guarded migration applier, shared free-tier credential owner and infrastructure generator for BiasLens alone. It generates secrets on the existing box without printing values. The observed older three-column Prisma Article table is preserved under `Article_prisma_legacy_20261023` before applying the canonical schema; records are not deleted or backfilled with invented content. Production setup requires the existing repository deploy secret and org host variable. This adds no paid service.

`pnpm run verify` includes an isolated Postgres-compatible integration test that executes the committed migrations and checks registration, session persistence, password rejection, sign-out and sign-in. Real provider and public deployment checks are separate.


The implementation incorporates the core first-principles analysis shape from
the earlier `bitbaum/truthseeker` repository. The original repository is
intentionally retained as migration history and rollback.

## Rebranding and editorial publishing

The product name is **BiasLens**. The existing repository and host identifiers remain unchanged. The repository slug, internal AI prefix,
deployment slug and database name are implementation identifiers, **not** public
brand commitments. All rendered names, the logo slot and social metadata are
derived from `src/lib/config/brand.ts`:

```dotenv
NEXT_PUBLIC_PRODUCT_NAME="Your future name"
NEXT_PUBLIC_PRODUCT_MARK="YN"
NEXT_PUBLIC_PRODUCT_LOGO="/brand/logo.svg"
NEXT_PUBLIC_SITE_URL="https://your-real-domain.example"
```

The logo URL points to a first-party static asset under `public/`, which can
be replaced independently of the app. Set `NEXT_PUBLIC_SITE_URL` only after
the real hostname is registered; pages are **noindex** in the absence of a
canonical URL. The application must be rebuilt after these build-time public
values change. Identity/roadmap content remains canonical in Loki/Fleet.

The journal is `/blog`, with `/blog/[slug]` and `/blog/feed.xml` (RSS is
available after a real origin is configured). Markdown lives in `content/blog`
and renders via the shared `bip-kit` reader and React renderer. Publishing
is a source-controlled PR with a reviewed date, title, evidence and explicit
uncertainty; there is no unattended AI publishing or invented public findings.
The roadmap and changelog stay in Loki and are not maintained as blog copies.

## Run locally

Requires Node.js 24 (CI version), pnpm 11 and optionally PostgreSQL for the
existing Drizzle schema.

```bash
pnpm install --frozen-lockfile
cp .env.example .env
pnpm run dev
```

Set **at least one** model credential in your local `.env` for AI analysis:
`GROQ_API_KEY` and/or `OPENROUTER_API_KEY`. The shared
`@bitbaum/ai-kit` controls model selection and cross-vendor fallback.
The HTTP reader comes from `@bitbaum/ai-kit/web`; request throttling from
`limitkit`. Neither uses a separate app-specific implementation.

Only if provisioning the research database:

```bash
pnpm run db:migrate
```

When AI keys are missing, `POST /api/analyze` returns an explicit 503 rather
than pretending the analysis ran. Fetch-restricted publishers can be analysed
through pasted text, but its source URL is then *user asserted*, not confirmed.

## Verification

```bash
pnpm run verify
pnpm run build
```

CI runs formatting, lint, TypeScript, design consistency/accessibility checks, unit and HTTP-boundary tests, then a
production build. Use `pnpm run design:check` to run the design gate directly. Tests use injected reader/model implementations and do not
fetch live pages or spend provider tokens.

## Openness

The code is MIT-licensed. The methodology is published with its limitations
and [a public challenge template](.github/ISSUE_TEMPLATE/methodology-challenge.yml).
AI replies to future challenges must remain identifiable as AI and never
automatically erase or close a human disagreement.


## Package composition

`package-plan.json` records the feature-to-package bindings. Review Fleet
`SHARED.md` and update this plan before implementing a feature. Sitekit renders
the root shell and public entry blocks; accountkit supplies account screens,
runtime and menu; bip-kit renders articles, reading progress, roadmap and
changelog; design-tokens supplies the complete theme and self-hosted fonts.
Local modules configure identity, content and theme roles or implement BiasLens
investigation behavior. Shared blocks are fixed in their owning repositories.

The shared composition workflow checks actual imports/usages and the dependency
update path. `browser:smoke` checks the real responsive menu, keyboard dismissal,
active state, root-shell coverage and font loading. Shared improvements propagate
through released versions, dependency PRs, checks, merge and the existing deploy.
