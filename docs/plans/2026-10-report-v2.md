# BiasLens report v2 — execution plan

Written 2026-10-26 for an executing agent. This is a working build plan, not the
canonical roadmap (that stays in Loki). Each numbered PR below is meant to be
one pull request: small enough to review, with its own acceptance checks. Do them
in order unless a step says it can run in parallel.

Before every PR: read `AGENTS.md`, `docs/design-contract.md`, Fleet `AGENTS.md`
and `SHARED.md`. Run `pnpm run verify`, `pnpm run build` and
`pnpm run browser:smoke`, and look at every changed screen at 390, 834 and 1440px.

---

## 1. Why the current report is weak

From reading `src/lib/domain/first-principles.ts`, `src/lib/analysis/run.ts` and
`src/app/analyze/AnalyzeWorkspace.tsx`:

1. **It is mostly prose.** `first_principles_critique`, `biases_to_consider` and
   `what_would_change_assessment` are free-text strings. Nothing in them is
   checked or tied to a passage, and nothing can be counted or compared. They
   read as generic because nothing forces them to be specific.
2. **The overview shows the wrong numbers.** "4 claims examined · 3 quoted
   passages · 2 named sources" describes our process, not the article.
3. **It doesn't say who is speaking.** Author and publication are bare strings.
   `named_sources` has no affiliation, no stance and no balance. A reader can't
   see whose voices the article relies on, or who employs the author.
4. **There is one shallow model call.** A single free-tier call with an
   18k-character limit and 3,600 output tokens does extraction, judgement and
   writing all at once.
5. **Quotes are dropped too easily.** A quote has to match the text byte for
   byte, so a typographic apostrophe or a line break discards a correct quote.
   There are no character offsets, so the article can't be highlighted.
6. **Nothing is saved.** With no persistence there's no link, no share card, no
   cache, and no build-up of records per author or outlet.
7. **Nothing to do afterwards.** The only follow-ups are a chat box and a JSON
   download, so there's no reason to come back or to share.
8. **The schema invites a political scale.** `EditorialDna.dimensions` is
   "dimension → score (-1..1)", which is a left/right meter waiting to happen.

## 2. Product rules (apply to every PR)

**Words we don't use as our own labels.** BiasLens never classifies a person,
outlet or article as left, right, liberal, conservative, progressive,
far-right, extremist, biased, propaganda, mainstream, alternative, or any
equivalent in DE/FR. These words may appear only inside verbatim quotations,
or when attributed to a source by name ("describes itself as …" with a link).

- Put the list in one place: `src/lib/config/vocabulary.ts` →
  `SYSTEM_FORBIDDEN_LABELS` (en/de/fr).
- After validating any model output, scan every reader-facing field except
  `quote`/`source_quote` fields. If a field contains a forbidden label, treat it
  as a schema failure and send it through the existing single repair.
- Add a unit test that runs the scan over every UI string under
  `src/app/**/*.tsx` as well.

**What we describe instead.** We describe what can be observed or traced to a
source:

- facts with a source: employer, ownership, funding model, party membership
  (Wikidata P102 is a recorded fact, not a label), offices held, the outlet's
  own stated mission (quoted)
- measurements from the text: whose voices are quoted, which techniques appear,
  which numbers lack a source
- value premises, named explicitly (section 6), instead of positions on a line

**Every judgement needs a passage.** A technique flag, a voice or a claim is
rendered only if its quote is found in the examined text (with normalised
matching, PR 2). Otherwise it's dropped, and the drop is counted in the
provenance block.

**Every profile fact needs a source.** Each line in a profile has a source URL
and a retrieval date. A model may arrange facts but never supply one; enforce
this with `ai-kit/grounding`.

**Simulations are labelled.** Any rewrite in the voice of a real outlet or
person says "Simulation, not written by X" in the text, on the page and inside
the share image itself. It never puts an invented quotation in a real person's
mouth.

**Open method.** Every technique, perspective and data source is defined in
config, rendered on `/methodology`, versioned, and can be challenged.

## 3. Phase 0: measure before improving

### PR 0 — evaluation harness

- `eval/articles.json` lists about 12 public articles on 4 current stories,
  covering at least: Weltwoche, Republik, NZZ, WOZ, Tages-Anzeiger, Blick, SRF,
  one English broadsheet and one English tabloid, plus a mix of news, opinion
  and interview. Store URLs and human notes only, never the article bodies.
- Commit 3 synthetic fixtures (fictional articles) under `eval/fixtures/` for CI.
- `pnpm run eval:reports` (not part of `verify`; it needs API keys) runs the
  pipeline and writes `eval/out/<promptVersion>/<id>.json` plus a summary table
  with these columns:
  - quote grounding rate (rendered ÷ proposed)
  - forbidden-label hits
  - number of detections
  - voices found compared with a hand count in `articles.json`
  - wall time
  - model id
- A human score sheet `eval/RUBRIC.md` scores each report 0–2 on:
  - specificity
  - correctness
  - usefulness to a reader who disagrees with the article
  - usefulness to a reader who agrees with it
- Record the current baseline (`first-principles@3`) before changing anything.
  Every later PR that touches prompts reports its delta against this baseline
  in the PR description.

## 4. Phase 1: a report worth reading

### PR 1 — technique catalogue (pure config + methodology page)

- `src/lib/domain/techniques.ts` is the SSOT. Each entry has `id`, `name`
  (en/de/fr), `definition`, `counts_when`, `does_not_count_when`,
  `why_it_matters`, and a fictional `example`. Starting set:
  - `loaded_term`: an evaluative word where a neutral one exists
  - `unattributed_assertion`: a factual claim in the author's voice with no
    source
  - `anonymous_source`
  - `one_sided_sourcing`: computed, not model-flagged (see PR 3)
  - `missing_response`: a party criticised with no reply sought or reported
  - `number_without_base`: an absolute number with no denominator, base rate,
    trend or comparison
  - `causal_leap`: correlation or sequence presented as cause
  - `speculation_as_fact`
  - `headline_body_gap`: the headline claims more than the body supports
  - `characterisation_of_person`: an adjective about a person in place of what
    they did
  - `scare_quotes`
  - `agentless_passive`: hides who acted
  - `emotional_appeal`: an image or anecdote carries the argument in place of
    evidence
  - `false_dichotomy`
  - `omitted_context`: only when the article itself hints at the context
- `/methodology` renders the catalogue from this file. Remove any hand-written
  copy of it.
- Tests check that every id is unique and that every language has every field.

### PR 2 — normalised quote matching with offsets

- `src/lib/analysis/quote-locate.ts` exports
  `locateQuote(text, quote) → {start, end} | null`. Use it everywhere a quote is
  checked: the claims, `article-chat`, and every new quote field.
- Normalise for matching only: Unicode NFC; typographic quotes and apostrophes
  to ASCII; dashes; collapsed whitespace; soft hyphens removed. Keep an index
  map so offsets point into the original text.
- Return the original substring, not the model's string, so what we show is
  always the article's own bytes.
- Unit tests cover curly quotes, line breaks inside a quote, German „…“,
  French « … » with non-breaking spaces, and a near-miss that must still fail
  (one changed word).

### PR 3 — report v2 contract and a three-pass pipeline

Replace the single call with three bounded passes. Each pass validates and
repairs separately. The code (`src/lib/analysis/run.ts`) stays dependency-
injected so tests never call a model.

1. **Extraction pass** (`extract@1`) returns JSON:
   - `genre`: one of `news_report | opinion | analysis | interview |
     press_release | feature | other`, plus a one-line reason
   - `byline`: `{author_names[], publication, date}` as printed
   - `central_claim`: `{text, quote}`
   - `claims[]`: the existing claim fields, plus `quote` and `speaker`
     (`author` or a voice id)
   - `voices[]`: one entry per person or organisation quoted, paraphrased or
     cited, with:
     - `id`, `name`
     - `affiliation_as_stated` (exactly as the article describes them, or
       null)
     - `kind`: `person | organisation | document | anonymous`
     - `quotes[]`
     - `stance_to_central_claim`: `supports | opposes | mixed | neutral |
       unclear`
   - `numbers[]`: `{value_text, quote, has_source, has_comparison}`
2. **Technique pass** (`techniques@1`) gets the text and the catalogue ids with
   definitions. It returns `detections[]` = `{technique_id, quote, explanation,
   neutral_alternative}`. Cap it at 12 detections. Prompt rule: "zero
   detections is a valid answer; report only what the definition covers."
3. **Synthesis pass** (`synthesis@1`) gets the validated output of passes 1 and
   2, not just the raw text. It returns:
   - `insight`: as today
   - `strongest_case`: the best version of the article's argument
   - `strongest_objection`: the best objection, written as its holders would put
     it
   - `missing_voices[]`: who has a stake but isn't heard, and why that matters
   - `questions_to_ask[]`: 3 concrete questions a reader could put to the
     author
   - `what_would_change[]`: specific evidence, each item one sentence

Then code (not the model) computes `metrics` in
`src/lib/analysis/metrics.ts`. These are pure functions, unit-tested, and each
is documented on `/methodology`:

- `voice_balance`: counts by stance; share of quoted words by stance
- `author_voice_share`: the share of text that is the author's assertion
  rather than quotation
- `unsourced_numbers`: count and list
- `anonymous_sources`: count
- `detection_counts` by technique
- `one_sided_sourcing`: true when ≥ 80% of voices with a known stance share
  one stance and at least 3 voices have a known stance. Store the threshold in
  config and state it on `/methodology`.

Other changes in this PR:

- Bump the prompt version to `report@4`.
- Keep `FirstPrinciplesAnalysis` readable for exported v3 JSON files (keep the
  parser, mark it legacy). The new type is `ReportV4`.
- Each pass gets its own `maxTokens`. Raise `MAX_MODEL_CHARS` to the chain's
  context limit; check ai-kit for the per-model limit rather than guessing.
- Add an env-selectable tier: by default `freeChain('BIASLENS')`, or
  `BIASLENS_ANALYSIS_CHAIN=quality` for the synthesis pass. Ask ai-kit for its
  non-free chain. Don't hand-roll vendor calls.
- Add the forbidden-label scan from section 2 to every pass's validation.
- Acceptance: on the eval set, quote grounding ≥ 90%, forbidden-label hits 0,
  and every report has ≥ 1 voice when the article quotes anyone. Paste the eval
  summary table in the PR.

### PR 4 — the new report screen

One page, top to bottom:

1. **Masthead.** Title; a genre badge in words ("Opinion piece"); the byline as
   links (author and outlet chips that open profile sheets once PR 6 lands; for
   now, plain text).
2. **At a glance.** One factual sentence built in code from `metrics`, not
   written by the model. For example: "Opinion piece. 9 voices quoted: 7
   support the central claim, 1 opposes, 1 unclear. 3 figures have no source.
   The criticised party's response is not reported." Remove the
   "Claims examined" counter row.
3. **The key assumption.** `insight`, as today.
4. **Annotated article.** The examined text with highlights from offsets
   (claims, detections, voices). Toggle chips across the top: Techniques,
   Voices, Claims, Numbers (one row that scrolls on a phone, never wrapping).
   Tapping a highlight opens a bottom sheet with the technique name, its
   definition from the catalogue, the explanation, the neutral alternative, and
   "Disagree with this flag" (wired in PR 12).
5. **Voices.** One row per voice: name, stated affiliation, stance, number of
   words quoted. Above the rows, a single stacked bar of stance shares with
   text labels (`chartkit` if it fits, otherwise plain CSS bars; colour is never
   the only signal).
6. **Strongest case / strongest objection**, side by side from md, stacked on a
   phone.
7. **Missing voices · Questions to ask · What would change this.**
8. **Actions.** One primary button, "Share", plus secondary "Rewrite…" (PR 9)
   and "Ask about this article" (the existing chatkit conversation).
9. **Provenance.** As today, plus the pass versions, model ids per pass and how
   many proposed quotes were dropped.

The component must stay under 300 lines. Split it into
`src/app/analyze/report/*` (`Masthead`, `AtAGlance`, `AnnotatedText`,
`VoicesList`, `DetectionSheet`, `Provenance`).

Show progress per pass ("Reading · Finding voices · Checking techniques ·
Writing the summary"), streamed from the route as NDJSON events, so a
60-second wait reads as work. Not as a spinner.

## 5. Phase 2: who is speaking

### PR 5 — byline and metadata extraction

- Get the author and publisher from page metadata before asking the model:
  JSON-LD `NewsArticle.author` / `publisher`, `meta[name=author]`,
  `article:author`, `og:site_name`. Find out whether `@bitbaum/ai-kit/web`
  `readPage` exposes raw HTML or metadata. If it doesn't, add a `metadata`
  field to ai-kit upstream (the fleet rule: extend the shared reader, don't fork
  it), release it, then consume it here.
- When metadata and the model's byline disagree, use the metadata and say which
  one was used.

### PR 6 — entity profiles (people and outlets)

Data, in a new migration:

- `Entity` (`id`, `kind`: `person|organisation`, `name`, `aliases[]`,
  `wikidataQid?`, `slug`, timestamps).
- `EntityFact` (`entityId`, `property`, `value`, `valueEntityId?`,
  `sourceUrl`, `sourceKind`: `wikidata|wikipedia|outlet_page|web`,
  `retrievedAt`, `validFrom?`, `validTo?`).
- `EntityLink` (`reportId`, `entityId`, `role`:
  `author|publisher|quoted|mentioned`, `confidence`, `confirmedBy?`).
- Replace `EditorialDna.dimensions` (-1..1) with nothing. Drop the table in
  this migration and remove its type. Outlet facts come from `EntityFact`;
  measured patterns come from saved reports (PR 7).

Resolution, in `src/lib/entities/resolve.ts` (pure, with injected fetchers):

1. Search Wikidata (`wbsearchentities`, free, CC0) by name.
2. Score candidates by context: for an author, occupation journalist/writer
   plus an employer that matches the publication; for a voice, the stated
   affiliation matched against employer, position or party.
3. Link automatically only when confidence ≥ 0.85 and the runner-up is far
   behind. Otherwise show "Possible matches" and let the reader choose. A
   reader's choice is stored as `confirmedBy`. Never auto-link a common name
   on a weak match: a wrong profile on a real person is the worst failure this
   feature can have.

Facts to pull:

- **Person:**
  - occupation (P106)
  - employer (P108)
  - position held (P39, with qualifiers for dates)
  - member of political party (P102)
  - member of (P463)
  - notable works
  - official website
  - the first paragraph of Wikipedia in the UI language, with link
- **Outlet:**
  - owned by (P127): walk the chain up to 3 levels
  - founded (P571)
  - country
  - language
  - legal form
  - publisher
  - editor-in-chief (P5769)
  - official website
  - the Wikipedia summary
  - the outlet's own "about us" or mission page found through `ai-kit/web`
    search, quoted, never summarised into a label

Model use:

- A model may write a two-sentence profile intro, but only from the fetched
  `Fact`s, verified by `ai-kit/grounding`. An unverified sentence is dropped.

UI:

- A profile sheet from any byline or voice chip.
- Public pages at `/people/[slug]` and `/outlets/[slug]`. Each fact line shows
  its source and date. The footer reads "Is something wrong? Tell us", which
  opens a GitHub issue template or a threadkit thread.
- Show no score, rating or label about the person or outlet.

Cache: facts refresh after 30 days. Fetch on demand when a report is opened,
never in a batch crawl.

### PR 7 — the BiasLens record (after PR 8 persists reports)

- On a profile, a section "In reports on BiasLens" with:
  - the number of public reports
  - the genre mix
  - the most frequent techniques, each linked to its examples
  - the average voice balance
- Always show `n` and this caveat: "Articles here were chosen by users, not
  sampled. This describes these N articles, not the author's work."
- Hide the section when n < 5.

## 6. Phase 3: links that travel

### PR 8 — save, cache and permalink

- `Report` table:
  - `id` (a short, URL-safe id)
  - `url?`, `urlCanonical?`
  - `textSha256`
  - `promptVersion`
  - `json` (the report)
  - `excerpts`: only the matched quotes, not the full text
  - `visibility`: `public | unlisted | private`
  - `ownerUserId?`
  - `createdAt`
- Store the full article text only for the owner, and only with an account,
  for re-analysis. A public page shows the quotes and a link to the original;
  that's what makes public storage lawful.
- Defaults:
  - a URL-fetched article is `public`
  - pasted text is `unlisted`
  - signed-in users can set `private`
- Cache: the same `urlCanonical` + `promptVersion` returns the stored report
  instantly ("Analysed 3 hours ago · Analyse again"). Re-analysing a cached URL
  doesn't count against the hourly limit.
- `/r/[id]` renders the saved report with the PR 4 components and a primary
  accent CTA "Examine your own article" (a public, top-of-funnel surface).
- Deep links: `/r/[id]#d-3` opens with detection 3 highlighted and its sheet
  open.
- The existing JSON export stays.

### PR 9a — share cards

- Use `next/og` `ImageResponse` routes under `/r/[id]/card/[kind]` in sizes
  1200×630 (OG), 1080×1080 and 1080×1920 (story).
- Card kinds:
  - `insight`: the headline of the key assumption, with outlet and title
  - `voices`: the stance bar plus the at-a-glance sentence
  - `detection`: the highlighted quote, the technique name and its one-line
    definition
  - `rewrite`: two columns, "Original" and "Rewritten", from PR 10
- Every card carries the BiasLens mark, "AI analysis · method v4" and the short
  URL. Rewrite cards also carry "Simulation" in the image.
- Fonts come from design tokens, which ship the faces. Load the font file
  explicitly for ImageResponse.
- One "Share" button: the Web Share API with the image file where supported
  (phones). Otherwise a sheet with: Copy link, Download image, X, Bluesky,
  LinkedIn, WhatsApp, Telegram, Reddit, Email, as prefilled intent URLs. Every
  detection sheet and the voices section has its own share action using the
  matching card kind.
- Page metadata: `og:image` = the insight card, `twitter:card` =
  `summary_large_image`. Sharing to WhatsApp or Telegram then shows the card
  with no extra steps.

### PR 9b — ways in

- **Prefix URL.** `/<any article URL>`. For example
  `biaslens…/https://www.weltwoche.ch/…` runs or opens the report: a catch-all
  route that validates the URL and redirects to `/analyze?u=`. People learn it
  once and pass it on.
- **`/analyze?u=<url>`** starts immediately.
- **PWA share target.** Add `manifest.webmanifest` with a `share_target` so
  "Share → BiasLens" appears in Android's share menu from any news app. On iOS,
  publish a Shortcut link on `/how-to-share`.
- **Bookmarklet** on the same page.

## 7. Phase 4: rewrite studio

### PR 10 — rewrites with a fact check of the rewrite

Route `POST /api/rewrite`, with input `{reportId, mode, target?}`. Modes:

1. **`neutral`**: the same facts, with each flagged passage rewritten. The UI
   shows a diff in which every change links to the detection that caused it.
2. **`response`**: a reply (a letter to the editor or op-ed) to the article,
   using the strongest objection, the missing voices and the questions to ask.
   Offered as "a short reply" or "a full op-ed".
3. **`perspective`**: the same facts, written from explicitly stated value
   premises instead of left/right.
   - Use the 8 axes of the smartvote smartspider: open foreign policy, liberal
     economic policy, restrictive fiscal policy, law & order, restrictive
     migration policy, expanded environmental protection, expanded welfare
     state, liberal society.
   - The reader picks one or two axes to emphasise. Put the axes and their
     wording in `src/lib/config/perspectives.ts`, cite the source on
     `/methodology`, and have the output start with "Written from these
     premises: …".
4. **`outlet_style`**: "How would {outlet} write this?" Presets are outlets
   (institutions) first, in `src/lib/config/style-presets.ts`. Each preset
   has:
   - observable style traits (typical length, register, structure, use of
     irony, kind of headline, typical sources)
   - the outlet's own stated line, quoted with a link
   - no political label

   Start with: Weltwoche, Republik, NZZ, WOZ, Blick, Tages-Anzeiger,
   SRF News, and one English broadsheet and one tabloid. Mark the output
   "Simulation: not written by {outlet}".
5. **`author_style`**: phase 2 of the studio, after outlets prove out.
   - Only for public figures with a Wikidata entry as journalist, writer or
     politician and a substantial public body of work.
   - Never in the first person as a factual statement.
   - Never with invented quotations.
   - Always with "Simulation: not written by {name}".
   - Keep an opt-out list (`style-optouts.ts`) honoured with no questions
     asked.

After every rewrite, run the extraction pass on the output and compare its
factual claims with the original's. This is the scientific core of the
feature.

- Mark each claim **kept**, **dropped** or **added**. An added factual claim is
  flagged on screen: "This version introduces a claim that is not in the
  original: …"
- Show "Same facts, different framing", with the technique counts of the
  original and the rewrite side by side.

UI:

- `/r/[id]/rewrite` shows a mode picker (`SegmentedControl` style, one row),
  then the target picker, then a streamed output beside the original. The
  output can be shared through the `rewrite` card (PR 9a).
- Save each rewrite as `Rewrite` (`reportId`, `mode`, `target`, `json`,
  `factDiff`) so it has its own link.

Limits: a separate limitkit window, 6 per hour anonymous and 30 signed in.

## 8. Phase 5: reasons to return

These are independent of each other. Each one is a single PR.

- **PR 11a — Compare coverage.** Paste 2–4 URLs about one event and get one
  table: outlet · genre · voices by stance · techniques · central claim, plus
  "claims only one outlet reports". Later, suggest other coverage through
  `ai-kit/web` search ("Other outlets on this story").
- **PR 11b — Spot the technique (daily).** A short daily round built from real
  public reports:
  - Five highlighted passages; the player names the technique, or chooses "no
    technique".
  - A second round, "Which outlet wrote this?", shows a neutral rewrite and
    four outlets to choose from.
  - The result is a shareable grid of squares (no article text) plus a streak
    counter, kept in the browser for anonymous players and on the account for
    signed-in ones.
  - This is the Wordle-shaped loop: it teaches the method and spreads with
    no outrage involved.
- **PR 11c — Recent reports.** `/reports` lists recently analysed public
  reports and the most-analysed articles this week. There is no ranking of
  outlets or people by "bias" anywhere, ever.
- **PR 11d — My reports.** For signed-in users: history, private reports,
  re-run on a new method version, and a comparison of what changed between
  versions.

## 9. Phase 6: open to challenge

### PR 12 — disputes and published accuracy

- "Disagree with this flag" on every detection, voice stance and profile fact.
  It takes a reason category and free text and is stored as a `Challenge` (use
  `threadkit` if it fits, per SHARED.md).
- `/methodology/accuracy` renders, per technique and per prompt version:
  - the number of detections
  - the share disputed
  - the share upheld or overturned on human review
  - the eval-set scores from PR 0
- A dispute that is upheld changes the saved report (with a visible
  "Corrected" note and the history), never silently.
- A method change log in `docs/methodology/` that bumps
  `METHOD_VERSION` per release.

## 10. Risks

| Risk | What to do |
| --- | --- |
| A wrong profile linked to a real person | High confidence threshold, show possible matches, a sourced fact per line, one-click report, fix within 48 hours |
| A simulation mistaken for a real text | Label in the text, page and image; no invented quotes; opt-out list |
| Copyright from storing articles | Public storage holds excerpts only; full text is private to the owner |
| Free-model quality limits | The PR 0 harness decides; the synthesis pass can use the `quality` chain by env flag |
| Labels creeping back in | The vocabulary scan on model output and UI strings, in `verify` |
| Outrage loops | No bias leaderboards; the game rewards recognising techniques, not hating outlets |
| Cost when something goes viral | URL cache (PR 8), cached share cards, separate rate limits per action |
